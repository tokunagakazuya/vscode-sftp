# Repository Guidelines

## Project Structure & Module Organization
- `src/`: TypeScript source for the VS Code extension.
  - `src/extension.ts`: entry point. `src/commands/`, `src/modules/`, `src/ui/`, `src/core/`: feature modules and UI.
- `dist/`: webpack build output; generated by `compile`/`dev` (do not edit).
- `schema/`: JSON schema for `.vscode/sftp.json` config.
- `resources/`, `assets/`: icons and images used by the extension.
- `test/`: Jest tests and helpers (`*.spec.js`, `preprocessor.js`). `__mocks__/` holds test doubles.
- `docs/`, `README.md`, `CHANGELOG.md`: user-facing documentation.

## Build, Test, and Development Commands
- `npm i`: install dependencies.
- `npm run dev`: webpack watch build to `dist/`; pairs with VS Code task in `.vscode/tasks.json` for live debugging.
- `npm run compile`: production bundle to `dist/`.
- `npm test`: run Jest test suite.
- `npm run package`: create `.vsix` via `vsce` (use `npx vsce package` if `vsce` is not installed).
- Debug: open in VS Code and run `Run and Debug > Launch Extension` (uses `.vscode/launch.json`).

## Localization (i18n)
- UI strings in `package.json` use VS Code NLS placeholders like `%key%`.
- Base strings live in `package.nls.json`; Japanese translations in `package.nls.ja.json`.
- Packaging: ensure `.vscodeignore` allows `package.nls.json` and `package.nls.*.json` so VSIX resolves placeholders. Already configured.
- To add/modify strings:
  - Replace literals in `package.json` with `%sftp.xxx%` keys.
  - Add the same keys to `package.nls.json` (default) and translate in `package.nls.ja.json`.
  - Verify in VS Code by switching display language to Japanese and reloading.

## Coding Style & Naming Conventions
- Language: TypeScript (target ES6). Enforced via TSLint (`tslint.json`).
- Style: single quotes, semicolons, 2-space indent, trailing commas on multiline objects/arrays, no redundant `public` members, minimal arrow parens.
- Names: `camelCase` for variables/functions/files, `PascalCase` for classes. Keep modules small and focused under `src/` subfolders.

## Testing Guidelines
- Framework: Jest. Tests live in `test/**/*.spec.js` and `**/__tests__/*.ts`.
- Run `npm test` locally; add unit tests alongside features (e.g., `test/core/scheduler.spec.js`).
- Use `__mocks__` for filesystem/VS Code API fakes. Prefer fast, deterministic tests.

## Commit & Pull Request Guidelines
- Commits: short, imperative subject lines (e.g., `Fix remote explorer refresh`, `Add Jest tests for config`).
- PRs: include a clear description, link related issues, and screenshots/GIFs for UI changes.
- Requirements: `npm test` green, `npm run compile` clean, docs/schema updated when configs change. Do not commit build artifacts in `dist/`.

## Push Policy and Permissions
- Always push your work when the task is complete so GitHub Actions can build and publish the VSIX for users to install.
- If a permission error occurs when committing or pushing (for example: cannot create `.git/index.lock`, permission denied, or rejected due to access):
  - Verify branch and remote: `git status`, `git rev-parse --abbrev-ref HEAD`, `git remote -v`.
  - Ensure you have write access and credentials are configured.
    - SSH: confirm `ssh -T git@github.com` succeeds and the repo remote uses SSH.
    - HTTPS: use a Personal Access Token with `repo` scope in your credential helper.
  - If a stale lock file exists: `rm -f .git/index.lock` and retry `git add/commit`.
  - Retry push: `git add -A && git commit -m "<message>" && git push`.
  - If environment-level restrictions block writes, ask the maintainer to grant push permission, then retry.

These steps ensure the CI pipeline produces the VSIX artifact for verification.

## Security & Configuration Tips
- Config lives in `.vscode/sftp.json` (validated by `schema/config.schema.json`). Never log or commit credentials.
- Use `sftp.debug` only when needed and avoid printing secrets in logs.

## User Communication Language
- Default: respond to users in Japanese unless explicitly requested otherwise.
- Developer-facing content (source code, commit messages, AGENTS.md, etc.) should remain concise English to conserve tokens.
